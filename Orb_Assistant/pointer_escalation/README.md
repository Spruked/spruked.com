# Pointer Escalation Contracts

This folder gives Spruked Orb Assistant access to the shared Orb Weaver pointer runtime and human-escalation contract set.

It is intentionally copied from Orb Weaver's `Orb_Assistant/pointer_escalation/` folder, with Python cache files omitted. Treat it as a contract folder: integration code may wire into it, but should not weaken the state order, confidence gates, or escalation guardrails.

## Purpose

The pointer escalation layer protects CALI from unsafe navigation and unsafe visual guidance.

It exists so the ORB can:

- resolve visitor intent against known pointer targets
- verify route and target identity before movement
- refuse uncertain, stale, missing, hidden, conflicting, or invalid targets
- route unresolved cases into recovery/owner review/human escalation
- preserve the point → ping → ploop lifecycle only for verified targets

## Spruked runtime rules

1. The ORB may point only to targets whose confidence/policy allow it.
2. CALI must never move after saying she cannot confirm the destination.
3. Route matching must be exact enough to distinguish product names and account/signup/checkout flows.
4. Pointer recovery may gather evidence, but may not overwrite canonical authority without verification.
5. Human escalation must be explicit or confirmed; frustration alone is not consent.
